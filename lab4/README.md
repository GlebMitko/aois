## Хеш-функция (из ЛР6)

### Преобразование букв в числа

Русский алфавит: А=0, Б=1, В=2, ..., Я=32

### Вычисление V (числового значения)

V = (код первой буквы) × 33 + (код второй буквы)

**Пример:**
- "Евразия": Е=5, В=2 → V = 5×33 + 2 = 167
- "Африка": А=0, Ф=21 → V = 0×33 + 21 = 21

### Вычисление хеш-адреса

h(V) = V mod H + B

**Пример:**
- H=20, B=0 → h = V % 20
- "Евразия": 167 % 20 = **7**
- "Африка": 21 % 20 = **1**

## Структура ячейки (строки) хеш-таблицы

Согласно рисунку 1 из ЛР6:

| Поле | Название | Описание |
|------|----------|----------|
| ID | Идентификатор | Ключевое слово |
| C | Collision | 1 — была коллизия, 0 — нет |
| U | Used | 1 — ячейка занята, 0 — свободна |
| T | Terminal | 1 — конец цепочки, 0 — есть продолжение |
| L | Link | 1 — Pi это указатель, 0 — Pi это данные |
| D | Deleted | 1 — запись удалена, 0 — активна |
| Po | Pointer overflow | Адрес следующей ячейки в цепочке |
| Pi | Pointer info | Данные или указатель на данные |

## Разрешение коллизий: линейный поиск

При коллизии (хеш-адрес уже занят) выполняется последовательный поиск свободной ячейки:

```
index = (hash_addr + 1) % size
index = (hash_addr + 2) % size
...
```

### Пример цепочки

```
Ячейка 7 (Евразия) → Po=8 → Ячейка 8 (Европа) → Po=16 → Ячейка 16 (МарианскаяВпадина) → Po=-1
```

## CRUD операции

| Операция | Метод | Описание |
|----------|-------|----------|
| **C**reate | `insert(key, data)` | Добавление новой записи |
| **R**ead | `find(key)` | Поиск записи по ключу |
| **U**pdate | `update(key, new_data)` | Обновление данных |
| **D**elete | `delete(key)` | Удаление записи (флажок D=1) |

### Особенности

- **Запрет дубликатов** — ключ должен быть уникальным
- **Удаление** — физически не удаляет, только устанавливает D=1
- **Поиск** — идет по цепочке Po при коллизиях
